# Thesis Lock — Catalog-Driven Order Orchestration vs. Intent-Based Agentic Commerce

**Sector:** Telecom (primary) — real fit with Northgate's actual BSS/OSS modernisation and TM Forum eTOM/process-architecture expertise.

**Source:** user-supplied draft (Order Management System POV). Technical grounding (TMF620 Product Catalog, TMF622 Product Order, 5G network slicing, MEC) verified against known TM Forum Open API naming — consistent with real, established standards, not invented.

**Thesis (one sentence):** You can't catalog your way out of a problem that changes in real time — when the requirement is dynamic, the architecture has to be too.

**3-point structure:**
1. Intent, not SKUs — declarative outcome capture replaces line-item selection
2. Real-time composition — an agent layer assembles the fulfillment path against live network/partner state
3. Self-healing, not fallout — failures re-route automatically instead of dropping into a manual queue

**Proof anchor:** pattern claim, not an external stat — TMF620/622's rigid catalog-to-order mapping is real and correctly named; the *magnitude* claims in the source document (cycle times "slashed to seconds," "near-zero" fallout) are directional and unsourced, so they're carried as qualitative architecture contrasts, not asserted as measured figures. This keeps the piece inside brand-voice's no-fabrication rule.

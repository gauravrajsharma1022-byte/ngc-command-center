01 Context

A firewall that was flying blind

The network could stop traffic, but it could not name a sender.

The operator already ran a capable SMS firewall. But its decisions were made on content patterns and volume heuristics — never on who was actually sending. Enterprise traffic arrived through a dozen aggregators with no consistent brand identity behind it.

Legitimate senders were throttled by false positives. Bad actors rotated sender IDs faster than rules could follow. A2P revenue leaked through grey routes, and smishing complaints were climbing quarter on quarter.

The registry model — proven at scale in US 10DLC — offered the fix: make every campaign carry a verified brand identity and a declared use-case, and let the network act on it.

02 The challenge

Five gaps between the traffic and the truth

Every gap traced back to the same missing thing — verified identity.

01

No sender accountability

MT traffic could not be tied back to a vetted, legally identified brand.

02

Policy on proxies

Filtering decisions ran on content and volume signals, not on identity or intent.

03

Fragmented onboarding

Each aggregator ran its own enterprise vetting — to its own standard, or none.

04

Blunt monetisation

Allow or block. No way to tier throughput or bill by campaign class.

05

No feedback loop

Complaints and STOP commands never flowed back to inform sender reputation.

03 Solution architecture

A control plane beside the network — never in the path

Identity flows in, reputation flows out, and not a single message hop is added to the SMPP delivery path.

Identity & approvals Message flow (MO / MT) Reputation feedback

The SMPP delivery path is untouched — the registry adds no hop and no transit latency. Enrichment is an out-of-band, cached lookup at the filter.

04 Integration detail

Six interfaces, eight systems

A thin control-plane surface, wired into the systems that already run the traffic.

Enablement API
REST / JSON pull of brand & campaign records; webhook subscriptions for status and trust-score changes.
Campaign cache
Local cache in the firewall for sub-millisecond lookup on MT, with a fail-open policy when the registry is unreachable.
Number binding
Sender ID, short code and 10DLC number associated to an approved campaign ID — enforced at the gateway.
Event stream
Firewall → message bus → TCR Vendor API: blocked, flagged, complaint and spam-type events, per sender.
CDR enrichment
campaign_id stamped on every CDR for downstream rating, wholesale settlement and BI. This is where identity becomes revenue.
Reconciliation
Nightly SFTP full-set export for registry ↔ network integrity checks.

05 My role & approach

Owned the solution, end to end

Solution Architect — from the first workshop to the design-authority sign-off.

01

End-to-end solution design. HLD and interface specifications across all eight MNO systems, with the design authority sign-off to match.

02

The canonical data model. Brand, campaign, vetting score, throughput tier and number binding — one schema, agreed across network, IT and wholesale.

03

The policy decision logic. Allow / throttle / block as a function of registration status × trust score × violation ratio, mapped to SMSC rate classes.

04

The non-functionals. Dip latency budget, cache TTL, registry-unreachable fail-open, throughput tiers — designed before a line of integration code.

05

The test strategy. SIT against aggregator sandboxes; UAT with real enterprise sender samples across banking, logistics and public sector.

06

Architecture governance. Ran the design-authority cadence across network, IT, fraud, wholesale and legal to a single approved blueprint.
